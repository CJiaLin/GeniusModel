# Feature Engineering Patterns

特征工程常用模式与最佳实践技能包。

## 适用场景

- 表格数据的特征工程阶段
- 数值/类别/时间/文本特征处理
- 特征交互与高阶特征构造

## 包含章节

| 章节 | 内容 |
|------|------|
| numeric-transforms | 数值特征变换（对数、分箱、标准化、多项式等） |
| categorical-encoding | 类别特征编码（OneHot、Target Encoding、频率编码等） |
| datetime-features | 时间特征提取（周期、滞后、滑动窗口等） |
| interaction-features | 特征交互与组合（乘法交互、分组聚合、比率特征等） |

## 系统性特征工程方法论

### 覆盖度原则

好的特征工程方案应**系统性覆盖**所有适用的模式类型，而不是只选一两种：

1. **数值列**：至少从"变换"（log/分箱/幂变换）和"交叉"（比率/差值/乘积）两个角度各生成特征
2. **分类列**：至少从"编码"（OneHot/Target/Frequency）和"分组聚合"（groupby 统计）两个角度各生成特征
3. **时间列**：提取组件 + 周期性编码 + 时间差
4. **跨类型交叉**：分类×数值（分组统计）、数值×数值（比率/乘积）

### 数量目标

- **下限**：新特征数 ≥ 原始特征数 × 50%
- **建议**：对于竞赛级建模，新特征数可达原始特征数 × 100%~200%
- **原则**：宁可多生成再由后续模型/特征选择阶段筛选，不要在生成阶段过于保守

### 常见不足模式（Anti-patterns）

| 不足 | 表现 | 改进 |
|------|------|------|
| 只做编码 | 仅 OneHot/LabelEncode，无新信息 | 加交叉、聚合、变换 |
| 只做变换 | 仅 log/标准化，无交互信号 | 加比率、分组统计 |
| 忽略交叉 | 未利用列间关系 | 数值比率、分组聚合 |
| 过于保守 | "怕维度爆炸"只生成 2-3 个特征 | 模型有特征选择能力 |
| 忽略统计聚合 | 未按分组计算均值/标准差 | 增加 groupby 特征 |

## 使用原则

- 所有特征工程操作必须**仅基于训练集**拟合，然后 transform 到验证/测试集
- 避免数据泄露：不使用未来信息、不使用目标变量做特征
- 优先选择可解释、业务有意义的特征
- 生成后通过特征重要性验证，移除无效特征（但这是后续步骤，生成阶段不要自我限制）
